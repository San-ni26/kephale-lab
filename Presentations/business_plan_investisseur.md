## RÉSUMÉ EXÉCUTIF

**Kephale** est la première plateforme de streaming musical **all-in-one** conçue pour l'Afrique francophone. Elle combine en une seule application : streaming musical, Reels/Shorts, lives interactifs avec dons, vente directe de contenus et paiement natif en Mobile Money (Orange Money, Wave, MTN MoMo).

Avec **97% du développement terminé**, une architecture production-grade (NestJS + PostgreSQL + LiveKit + Expo), et **5 sources de revenus actives**, Kephale est prête au lancement commercial immédiat.

## 1. Le Problème & l'Opportunité

### 🔴 Un marché de 1,4 milliard de personnes largement ignoré

L'Afrique représente **17% de la population mondiale** et sa musique (Afrobeats, Coupé-Décalé, Afro-trap, Ndombolo, Mbalax) est consommée globalement — WizKid, Burna Boy, Tiakola ont des millions de fans en Europe et aux États-Unis.

**Pourtant, les grandes plateformes ont échoué en Afrique :**

| Problème | Impact réel |
|----------|-------------|
| Spotify non disponible dans 20+ pays africains | Millions d'utilisateurs exclus |
| Aucun support Orange Money / Wave / MTN MoMo | 0 revenu généré sur 800M de portefeuilles mobile money |
| Revenus artistes : ~0,003 € / stream | Un artiste avec 1M de streams gagne ~3 000 € |
| Pas de live avec dons monétisés | Canal de revenus direct inexistant |
| Contenus non localisés | Algorithmes calibrés pour public occidental |

> **💡 La réalité des chiffres :** En Afrique, 70% des paiements se font via Mobile Money. Aucune grande plateforme musicale ne l'accepte. C'est le principal frein à la monétisation.

## 6. Modèle Économique & Sources de Revenus

### 6.1 Système de tokens (monnaie interne)

```
10 tokens = 100 FCFA = ~0,15 € = ~0,16 USD

L'utilisateur achète des tokens avec son Mobile Money ou sa carte.
Il dépense les tokens pour acheter du contenu, s'abonner, donner en live.
Kephale retient une commission sur chaque transaction.
→ Modèle éprouvé : TikTok coins, Twitch Bits, V-Bucks (Fortnite)
```

### 6.2 Les 5 sources de revenus

#### 💎 Source 1 — Vente de packs de tokens

| Pack | Tokens | Prix (FCFA) | Prix (EUR) | Marge Kephale |
|------|--------|-------------|-----------|----------------|
| Starter | 100 | 1 000 | ~1,52 € | **100%** |
| Standard | 500 | 4 500 | ~6,86 € | **100%** |
| Pro | 1 200 | 10 000 | ~15,24 € | **100%** |
| Premium | 2 600 | 20 000 | ~30,48 € | **100%** |

#### 🎫 Source 2 — Abonnements mensuels

| Tier | Tokens/mois | Prix XOF | Prix EUR | Avantages |
|------|------------|----------|----------|-----------|
| **Free** | 0 | 0 | 0 | 3 écoutes gratuites/jour |
| **Premium** | 500 | 5 000 | ~7,62 € | 50 écoutes/mois illimitées |
| **Premium+** | 1 000 | 10 000 | ~15,24 € | 500 écoutes, DL offline |

#### 🎵 Source 3 — Vente de contenu (commission 20%)

```
L'artiste fixe son prix. Kephale retient 20%.
Exemple :
  Track à 500 tokens (5 000 FCFA / ~7,62 €)
  → Artiste reçoit 400 tokens
  → Kephale retient 100 tokens (~1,52 €)
```

#### 📺 Source 4 — Dons en lives (commission 15%)

```
Fan donne 100 tokens en live
→ Artiste reçoit 85 tokens
→ Kephale retient 15 tokens
```

#### 📣 Source 5 — Publicité & Boosts

| Format | CPM | Audience |
|--------|-----|----------|
| Vidéo dans Reels | 3–8 € | Tous users |
| Pré-roll clip | 5–12 € | Tous users |
| Audio spot | 2–5 € | Users Free |
| Track Boost | 50–700 tokens | Artistes |
| Album Boost | 50–700 tokens | Artistes |

### 6.3 Synthèse des marges

| Source | % Kephale | % Artiste |
|--------|-----------|-----------|
| Tokens (vente) | **100%** | — |
| Abonnements | **100%** | — |
| Publicité | **100%** | — |
| Vente contenu | **20%** | 80% |
| Dons live | **15%** | 85% |
| **Moyenne pondérée** | **~65%** | **~35%** |

> **💡 Insight :** La marge brute moyenne de **65%** est supérieure à celle de Spotify (~25%) car Kephale n'a pas de royalties fixes par stream — les artistes sont payés uniquement via les transactions réelles.

## 8. Architecture Technique & Infrastructure

### 8.1 Stack technologique

```
MOBILE (iOS + Android)          BACKEND                     INFRASTRUCTURE
──────────────────────          ───────                     ──────────────
React Native + Expo SDK 54      NestJS (Node.js 20)         PostgreSQL (Prisma)
Expo Router v6                  REST API + Socket.IO         Redis Upstash
Zustand + TanStack Query        BullMQ (tâches async)        Supabase S3
react-native-track-player       FFmpeg (transcodage)         LiveKit Cloud
LiveKit WebRTC                  Prisma ORM                   Expo EAS (builds)
MMKV (stockage local)           Stripe + CinetPay            Sentry + PostHog
DRM AES-256 (.keph)             21 mesures sécurité          Render.com (hosting)
```

### 8.2 Scalabilité technique

Le système est architecturé pour supporter **10M+ utilisateurs** sans refonte majeure :

| Composant | Capacité actuelle | Scalabilité |
|-----------|-----------------|-------------|
| API NestJS | 500 req/s | Horizontal scaling (Kubernetes) |
| PostgreSQL | ~1M rows/table | Read replicas configurés |
| Redis Cache | 10K req/jour (free) | Upstash Pay-as-you-go |
| S3 Supabase | 1 Go free | Migration AWS S3 à 0,023 $/Go |
| LiveKit | Pay-as-you-go | Jusqu'à 100 000 participants simultanés |

### 8.3 Conformité & Sécurité

- **21 mesures de sécurité** implémentées (audit complet réalisé en août 2026)
- Tokens JWT signés, refresh tokens hashés SHA-256 en base de données
- Chiffrement DRM AES-256 des fichiers hors ligne
- Rate limiting multi-couches (10/s burst, 120/min, 500/15min)
- Monitoring Sentry actif (erreurs + performance)
- GDPR-compliant (PostHog EU, aucun email en analytics)
